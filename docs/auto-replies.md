# 正则自动回复

在允许的 QQ 群内，按文件顺序匹配消息正文，命中第一条规则后向当前群发送配置中的固定文字。
规则和回复统一保存在 `ARK_DATA_DIR/auto-replies.toml`，默认是项目的 `data/auto-replies.toml`。
Docker Compose 已挂载 `./data:/app/data`，修改宿主机的这个文件即可生效。

## 初始化与校验

首次使用先同步新增依赖，再生成规则文件：

```text
uv sync --locked
uv run --locked ark-gacha replies init
uv run --locked ark-gacha replies check
```

`init` 生成的示例默认关闭；文件已存在时会报错退出，不会覆盖用户配置。
默认只保留 `#sl` 全文匹配、@机器人且正文含“是谁”两条规则，回复均留空供自行填写。
填写 `reply` 后，将文件顶部 `enabled` 改成 `true`。已运行的新版本机器人默认在 5 秒内加载变更。
首次安装本功能需要重启机器人；此后的规则修改不需要重启。
`check` 只读取和校验文件，不连接 QQ、不发送消息、不依赖卡池数据。
两个命令都支持 `--file <路径>`；该参数只影响这次 CLI 操作，机器人仍读取数据目录中的固定文件。

Docker 内校验已部署版本的规则：

```sh
docker compose exec bot ark-gacha replies check
```

## 文件示例

```toml
version = 1
enabled = false
reload_interval_seconds = 5
default_cooldown_seconds = 30

[[rules]]
id = "sl"
pattern = '#sl'
mode = "fullmatch"
reply = ""

[[rules]]
id = "who-is"
pattern = '是谁'
mode = "search"
require_at_self = true
reply = ""
```

填写回复并开启后，`#sl` 命中第一条，`#sl extra` 不命中。
第二条要求原始消息中包含真实的 @当前机器人消息段，且正文含“是谁”；@可以位于消息任意位置。
@其他人、@全体成员、只输入文字 `@机器人`、只引用机器人消息或喊昵称，都不能替代这个条件。
`reply` 留空或只有空白时，规则作为待填写草稿跳过，不发送空消息，也不阻挡后续规则。
TOML 单引号内的正则不需要额外转义反斜杠。需要忽略大小写时可写 `pattern = '(?i)hello'`。
回复按纯文本原样发送，支持换行；`[CQ:at,qq=all]` 也只会作为文字发送。
需要 @发送者请设置 `at_sender = true`，机器人会发送真实 OneBot @消息段。

| 字段 | 说明 |
|---|---|
| `version` | 必填，整数 `1` |
| 顶部 `enabled` | 功能总开关；省略默认 `true`，初始化示例显式设置为 `false` |
| `reload_interval_seconds` | 检查文件的间隔，默认 5 秒，允许 0.1～300 秒；修改间隔会在下一次检查后生效 |
| `default_cooldown_seconds` | 默认冷却，默认 30 秒；允许 0～86400 秒，0 表示无冷却 |
| `rules` | 必填，最多 200 条；清空规则可写 `rules = []` |
| 规则 `id` | 必填且唯一，1～64 个英文字母、数字、下划线或连字符 |
| 规则 `enabled` | 默认 `true`，可单独停用规则 |
| `pattern` | 必填，非空正则，最多 2048 字符；使用 `regex` 库的 VERSION0 行为 |
| `mode` | 默认 `search`，正文任意位置命中即可；`fullmatch` 要求整个正文匹配 |
| `reply` | 必填，固定回复，最多 4000 字符；空字符串或只有空白表示待填写，暂不参与匹配 |
| `at_sender` | 默认 `false`，是否 @发送者 |
| `require_at_self` | 默认 `false`；为 `true` 时要求原始消息实际 @当前机器人，且正则也命中 |
| `cooldown_seconds` | 规则冷却，省略继承全局默认；0～86400 秒 |
| `groups` | 字符串群号列表，例如 `["123456789"]`；省略或 `[]` 表示所有已允许的群 |

## 多行回复写法

把原来的 `reply = ""` 替换为下面这样的三单引号字符串，内容直接换行：

```toml
reply = '''
第一行内容
第二行内容
第三行内容'''
```

这会发送一条包含三行文字的消息。不要在同一条规则内再增加第二个 `reply` 字段。
开头三个单引号后紧接的第一个换行会被 TOML 去掉；例子把结尾引号放在第三行末尾，因此末尾没有额外换行。
如果把结尾的 `'''` 单独放一行，回复末尾也会保留一个换行；内容中的空行、缩进则按原样保留。

也可以在双引号字符串里用 `\n` 表示换行：

```toml
reply = "第一行内容\n第二行内容\n第三行内容"
```

两种写法得到相同的文字。单引号字符串不会解释转义，因此 `reply = '第一行\n第二行'` 会直接发送反斜杠和字母 n。
需要多行时推荐第一种写法，便于直接编辑；如果正文确实包含连续三个单引号，可改用三个双引号，但其中反斜杠要遵守 TOML 转义规则。
字符串与换行规则见 [TOML 1.0 字符串规范](https://toml.io/en/v1.0.0#string)。

在当前 `sl` 规则里，完整的写法如下。这里的文字只是说明示例，实际规则文件仍为你保留空回复：

```toml
[[rules]]
id = "sl"
pattern = '#sl'
mode = "fullmatch"
reply = '''
这里填写第一行
这里填写第二行'''
```

`reply` 是固定文字，不会自动替换正则捕获组、`{name}` 或 `$1`，也不执行代码。
换行会保留，但 Markdown 符号和 CQ 码只按文字发送。

## 正则说明书

本节面向当前机器人：正则使用 `regex` 库的 VERSION0 行为，模式写在 `pattern`，匹配方式写在 `mode`。
基础语法可参照 [Python 正则语法](https://docs.python.org/3.11/library/re.html#regular-expression-syntax)；
库的版本行为、标志位及超时说明见 [regex 官方项目文档](https://pypi.org/project/regex/)。
以下例子用于查阅，不会自动增加到正在使用的规则文件中。

### 先选匹配方式

| 目的 | `mode` | `pattern` | 会命中 | 不会命中 |
|---|---|---|---|---|
| 正文必须完整相同 | `fullmatch` | `#sl` | `#sl` | `#sl abc`、`abc#sl` |
| 正文中包含关键词 | `search` | `是谁` | `你是谁`、`是谁来了` | `你好` |
| 从正文开头匹配 | `search` | `^你好` | `你好呀` | `大家你好` |
| 从正文结尾匹配 | `search` | `再见\Z` | `明天再见` | `再见啦` |

机器人会先去除正文首尾空白，所以 ` #sl ` 也会按 `#sl` 匹配。内部空格、换行仍保留。
`search` 已经表示“任意位置包含”，匹配“是谁”直接写 `pattern = '是谁'` 即可，不需要前后加 `.*`。
使用 `fullmatch` 时，通常也不需要额外加 `^` 和 `$`。

### 常用符号速查

下表是正则表达式内容；放到文件时用 `pattern = '这里的表达式'` 包起来。

| 写法 | 含义 | 例子 |
|---|---|---|
| 普通文字 | 按文字匹配 | `是谁` 匹配连续的“是谁”二字 |
| `.` | 一个任意字符，默认不含换行 | `你.谁` 匹配“你是谁” |
| `*` | 前面的部分重复 0 次或更多 | `哈*` 可匹配空字符串、“哈”、“哈哈” |
| `+` | 前面的部分重复 1 次或更多 | `哈+` 匹配“哈”、“哈哈” |
| `?` | 前面的部分出现 0 次或 1 次 | `你好呀?` 匹配“你好”、“你好呀” |
| `{3}` | 恰好重复 3 次 | `[0-9]{3}` 匹配三位数字 |
| `{1,3}` | 重复 1～3 次 | `[0-9]{1,3}` 匹配一至三位数字 |
| `{2,}` | 至少重复 2 次 | `哈{2,}` 匹配至少两个“哈” |
| `[abc]` | a、b、c 中任意一个字符 | `[!！]` 匹配半角或全角叹号 |
| `[0-9]` | 一位 ASCII 数字 | `[0-9]+` 匹配一段数字 |
| `[A-Za-z]` | 一个英文字母 | `[A-Za-z]+` 匹配一段英文字母 |
| `[^0-9]` | 一个非 ASCII 数字字符 | `[^0-9]+` 匹配连续非数字字符 |
| `A\|B` | A 或 B | `早安\|晚安` 匹配两个词中的任意一个 |
| `(...)` | 将内容组成一组，并捕获匹配文字 | `(你好)+` 匹配重复的“你好” |
| `(?:...)` | 只分组，不捕获 | `(?:早安\|晚安)[!！]?` |
| `\d` | 一个 Unicode 十进制数字 | 仅接受 0～9 时优先用 `[0-9]` |
| `\s` | 一个空白字符，包括空格、制表符和换行 | `你\s*是谁` 允许中间有空白 |
| `[ \t]` | 一个普通空格或制表符 | `[ \t]+` 允许多个空格，但不跨行 |
| `\S` | 一个非空白字符 | `\S+` 匹配连续非空白文字 |
| `\w` | 一个单词字符，默认也可包含中文 | 只要英文、数字、下划线时用 `[A-Za-z0-9_]` |
| `\n` | 一个换行符 | `第一行\n第二行` 要求两行相邻 |
| `^` / `$` | 开头 / 结尾；`$` 也可位于末尾换行之前 | 精确整条匹配优先用 `fullmatch` |
| `\A` / `\Z` | 整段文字的开头 / 严格结尾 | 不受 `(?m)` 的逐行锚点行为影响 |
| `\b` | 单词字符与非单词字符之间的边界 | `\bcat\b` 不匹配 `catalog`；中文词语不宜直接依赖它分词 |
| `\.` / `\?` / `\+` | 匹配符号本身 | `1\.2` 匹配“1.2”，不匹配“1x2” |

`*`、`+`、`?` 和 `{...}` 默认只作用于紧挨着它们前面的一个字符、字符集合或分组。
例如 `你好+` 允许多个“好”，而 `(?:你好)+` 允许整个“你好”重复。
`.*` 可以匹配空字符串，单独配合 `search` 几乎会命中所有非空消息，通常不应作为自动回复规则。

### 可以直接改用的例子

只匹配 `#sl`，同时允许大小写变化：

```toml
pattern = '(?i)#sl'
mode = "fullmatch"
```

匹配“早安”或“晚安”，末尾允许一个全角或半角叹号：

```toml
pattern = '(?:早安|晚安)[!！]?'
mode = "fullmatch"
```

匹配 `#sl` 后跟一个或多个空格或制表符，再跟一至三位数字：

```toml
pattern = '#sl[ \t]+[0-9]{1,3}'
mode = "fullmatch"
```

会命中 `#sl 12`，不会命中 `#sl12`、`#sl 1234`，也不会跨行匹配参数。

正文同时包含“苹果”和“香蕉”，顺序不限，也允许跨行：

```toml
pattern = '(?s)\A(?=.*苹果)(?=.*香蕉).*'
mode = "fullmatch"
```

正文包含“福利”，但不能含有“广告”：

```toml
pattern = '(?s)\A(?!.*广告).*福利.*'
mode = "fullmatch"
```

`(?=...)` 表示后面的文字必须满足一个条件，`(?!...)` 表示不能满足这个条件；它们只检查位置，不消耗文字。
上面两个例子用 `\A` 固定在整段开头检查，避免 `search` 从后面的某个位置重新尝试而绕过排除条件。

### 大小写、换行与转义

| 标志 | 用途 | 例子 |
|---|---|---|
| `(?i)` | 忽略大小写 | `(?i)hello` 可匹配 `HELLO` |
| `(?s)` | 让 `.` 也能匹配换行 | `(?s)开始.*结束` 可跨多行匹配 |
| `(?m)` | 让 `^`、`$` 也匹配每一行的开头、结尾 | `(?m)^提示：` 配合 `search` 查找任一行的提示 |

`(?m)` 不会让点号跨行，也不会把 `fullmatch` 变成“任意一行完整匹配”。
多个标志可合并，例如 `(?is)` 同时忽略大小写并允许点号跨行。
量词默认尽量多匹配；`.*?`、`.+?` 表示尽量少匹配。对这里只判断是否命中的多数规则，通常不需要特意使用它们。

正则推荐用 TOML 单引号。以下两个 `pattern` 等价，都会匹配连续数字：

```toml
pattern = '\d+'
```

```toml
pattern = "\\d+"
```

不要写 `pattern = "\d+"`：TOML 双引号不支持 `\d` 这种转义。
这里也不使用 Python 的 `r'...'` 或 JavaScript 的 `/.../i` 写法。
`#` 放在普通字符串中可直接匹配，因此 `pattern = '#sl'` 不需要转义。
如果使用了扩展模式 `(?x)`，`#` 有注释含义，此时匹配它需写 `\#`。

### 与机器人行为有关的限制

- 正则只匹配原始消息里的文字部分，不检查图片内容，也不做 OCR。
- 要求 @机器人使用 `require_at_self = true`；回复时 @用户使用 `at_sender = true`，这两个字段作用不同。
- 同时匹配多条规则时只使用文件中靠前的那条；优先把具体规则放在宽泛规则前面。
- 修改前可运行 `uv run --locked ark-gacha replies check` 检查 TOML、字段和正则语法；它不会判断表达式是否符合你的语义，也不会向 QQ 发消息。
- 内容仍受群白名单、启用开关、空回复跳过、命令优先、冷却和去重限制。正则本身命中不代表一定发送。
- 避免不必要的复杂重复，例如 `(a+)+`；实际匹配受超时预算限制，超时会跳过这条消息的自动回复处理。

## 处理顺序

1. 只处理 `ARK_ALLOWED_GROUPS` 中的群；规则的 `groups` 只能进一步缩小范围。空白名单不响应任何群。
2. 忽略机器人自己的消息及私聊；提取原始消息的纯文字正文，去除首尾空白，保留内部空格和换行。
3. 已识别的抽卡、帮助及管理命令优先，包括命令的参数错误提示，不触发自动回复。
4. 跳过回复未填写或不满足 @条件的规则，按文件顺序寻找第一条启用且适用当前群的命中规则。一条消息最多发送一条自动回复。
5. 首条命中规则处于冷却时，不回复，也不尝试后面的规则。冷却按机器人账号、群、规则区分，不按用户区分。

冷却在发送前占用，同一群同时收到几条消息时也不会绕过冷却。
发送失败只记录规则 ID 与异常类型，不自动重试，也不撤销冷却，避免发送结果不明时重复回复。
同一机器人账号、群、消息 ID 在 10 分钟内只处理一次；冷却和去重都是内存状态，重启后重置。

## 加载与异常处理

- 加载时统一校验字段、规则 ID 和所有正则（包括停用规则），全部成功才整体替换。
- 正确配置保存后自动生效；修改相同 ID 的规则不会重置已经开始的冷却，也不会清空消息去重。
- 新配置损坏、文件被删除或读取失败时保留上次有效规则。关闭功能应保存 `enabled = false`。
- 启动时文件不存在或无效，自动回复保持关闭；机器人仍能执行抽卡命令，后续会继续检查规则文件。
- 同一份错误配置只记录一次加载告警。日志包含规则 ID 和字段错误，不记录收到的消息正文。
- 建议编辑完后一次保存；也可先离线校验临时文件，再通过重命名替换正式文件。

UTF-8 文件支持 BOM，文件上限 256 KiB。超过 8192 字符的消息不参与匹配，不会截断后误匹配。
正则在工作线程中执行，单规则最多约 10 ms，单条消息匹配预算 50 ms；超时结束本次匹配，记录规则 ID。
最多同时处理两条消息的正则匹配，繁忙时跳过额外消息，不排队阻塞抽卡处理。
去重和有效冷却各最多保留 10000 项，达到上限时跳过新处理，保留已有去重/冷却保护。
这些限制面向正常群聊负载，超时预算不是硬实时保证。

## 部署

本功能新增 `regex` 依赖，使用更新后的 `pyproject.toml` 与 `uv.lock` 同步环境；Docker 需要重新构建应用镜像。
历史 `0.1.2 → 0.1.3` 无依赖增量打包器会拒绝这次依赖变更，不能直接用于包含本功能的新源码。
0.1.4 已提供 [0.1.3 → 0.1.4 最小离线更新包](minimal-upgrade.md)，包内携带锁定的 Linux amd64 `regex` wheel。
规则文件属于运行数据，不打入公共部署包；源码包和 wheel 只包含默认关闭、回复留空的示例。
